# Online Novel Search WebApp (なろう小説 拡張検索サイト)

小説投稿サイト「小説家になろう」の公開APIを利用し、キーワードのAND検索とOR検索を組み合わせて作品を検索できるWebアプリケーションです。

## 制作背景（なぜ作ったか）

普段、趣味でネット小説を探していく中で、自分の好きなジャンルの小説のみを検索し、面白い小説を発掘したいという考えがありました。しかし、「小説家になろう」公式の検索機能はAND検索にしか対応しておらず、複数のキーワードを指定すると絞り込みが強すぎてしまい、逆にキーワードを減らすと絞り込みが甘くなるという不便さを感じていました。 これにより、自分の好きなジャンルに特化した検索ができなくなってしまいます。そこで、関連する複数のキーワードを「いずれかを含む（OR検索）」条件で指定し、好きなジャンルの小説をより網羅的に探せるようにするため、本アプリを開発しました。

## プロジェクト概要

公式APIには存在しないOR検索の要件をアプリ側のロジックで補完し、AND検索とOR検索の併用を実現しています。また、独自にフィルタリングを行った際にも、ページネーションやソート（並び替え）の挙動が崩れないよう状態管理を構築しました。

## 使用技術

- **バックエンド・ロジック**: C# 14, .NET 10    
- **フロントエンド・UI**: Blazor (Interactive Server), HTML5, CSS3, Bootstrap
- **外部連携**: なろうAPI

## 主な技術的課題と解決策

### 課題1：API仕様にない「ローカルOR検索」の実装

- **課題**: 公式APIには、指定したキーワードに対する純粋なOR検索機能が存在しませんでした。

- **解決策**: まずAND検索の条件でAPIから1回の通信上限である最大500件のデータを取得し、その中からC#のLINQ（`Where`, `Any`等）を用いてOR検索の条件に合致する小説をアプリ側でフィルタリングする二段構えのロジックを実装しました。

### 課題2：API取得上限（st=2000）に対応する非同期ページネーション

- **課題**: APIの取得開始位置（`st`）には最大2000件までという制約があるほか、1回（最大500件）の取得データをアプリ側でOR検索フィルタリングすると、1ページあたりの表示件数（20件など）に満たなくなる問題がありました。

- **解決策**: APIから取得・フィルタリングしたデータをローカルストック（最大2000件分の取得枠内）にプールし、画面表示用にLINQの `Skip` と `Take` で1ページ分の表示件数（20件など）を切り出すローカルページネーションを実装しました。ストック内の件数が表示件数に足りない場合のみ、上限（`st=2000`）の範囲内で `while` ループを用いて非同期でAPIから500件ずつ追加取得して継ぎ足す仕組みにしています。
    

### 課題3：Blazorの非同期ライフサイクルと再描画による重複表示の解消

- **課題**: ページネーションの実行中に、画面に表示されている小説リストが二重に増殖して描画されるバグが発生しました。

- **解決策**: デバッグの結果、`.ToList()` が毎回新しいインスタンスを返すため、Blazor側が参照の違いを見て「変更あり」と判断して再描画が走っていたことと、非同期処理の割り込み（フライング発火）が原因であると特定しました。そこで、参照比較に基づく状態変更検知変数（`_isFetchingMore`フラグ等）を導入して排他制御と状態のリセットを行うことで、UIの二重描画は再現しなくなりました。
    

## アーキテクチャと設計思想

- **関心の分離 (Component Design)**: 親コンポーネントにAPI通信とデータ抽出・状態管理を集約し、子コンポーネントはUIの描画と入力検知（`EventCallback`を用いた通知）のみを担当する構成にしました。UIの変更や通信ロジックの修正を行う際に、コードを触る範囲を狭くする意図で設計しています。

- **状態汚染の防止**: 検索条件の生成ロジックにおいて、フィールド変数ではなくメソッド内のローカル変数を用いるようにリファクタリングし、再検索時に前回の検索条件が残留しないようにしました。
    

## 今後の展望

- **SQLiteを用いたローカルデータベースによるお気に入り（一時ストック）機能の実装** ：公式のブックマーク機能では、気になった小説を「とりあえず登録」すると、自分に合わなかった際に後から解除する手間が発生します。この不便なUXを解決するため、本アプリ内に気になる小説を一時的にストックし、あとから精査できるローカル保存機能を実装予定です。
